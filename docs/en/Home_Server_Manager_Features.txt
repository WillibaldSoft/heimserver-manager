HOME SERVER MANAGER – OVERVIEW OF FEATURES
Status: Version 0.12-67 · October 10, 2026

The Home Server Manager consolidates the administration of a private Linux server
in a web interface. It is designed for desktop and smartphone.
Which features are usable depends on installed programs,
hardware and the respective setup.

1. OVERVIEW AND OPERATION
- Central start page with direct access to individual sections.
- Display of the computer name for distinguishing multiple servers.
- German and English for the web interface: navigation, module texts, forms, help, and messages. Custom names, paths, and original technical protocols are not translated.
- Password-protected access, password change, and configurable login duration.
- Local Linux accounts individually enabled for the manager;
  Login with Linux password, roles Administrator/User/Read Only.
- Selected modules and actions limited on the server side; independent
  Manager emergency access remains available; no automatic user enablement.
- Server backups remain reserved for administrators. Client backups
  continue to use their own profiles; agent tokens revoked separately.
- Download rights cover the entire configured download folder;
  they do not assume SMB/NFS file permissions.
- Hide or disable unused sections via module selection.

2. SHARES AND USERS
- Create, edit, and remove SMB and NFS file shares.
- Install required share services and verify their setup.
- Manage Linux users, groups, and SMB access points.
- Display and modify user and group permissions per share.
- Consider folder rights; mark unclear effective permissions clearly.
- Support optional domain setup for server or client respectively.
- Download helper files for setting up clients.

3. SERVERS AND SERVICES
- Display server status as well as running and failed services.
- Start, stop, restart services, and configure their auto-start.
- View service logs and service definitions.
- Compact service table with grouped actions and expandable hints.
- Optionally control OpenIPMI; compatible IPMI/BMC hardware is required.
  Inclusion in the overview does not automatically activate the service.
- Display system requirements and reasons preventing automatic sleep.

4. DISKS AND STORAGE
- Display disks, partitions, mount points, and storage usage.
- Check SMART status and disk warnings.
- Mark drives additionally with their mount names.
- Mount supported partitions and unmount them.
- Configure storage limits and associated warnings.

5. SLEEP AND WAKE UP
- Manage schedules for sleeping, shutting down, and waking up.
- Consider sleep blockers via devices, virtual machines, and running jobs.
- Account for TV recordings in wake-up planning.
- Specify per VM whether it stays awake or is shut down via Sleep & Wake.
- Managed VMs are shut down approximately five minutes before the scheduled server shutdown;
  schedule, cooldown period, and other blockers remain decisive.
- Upon manual shutdown in the manager, immediately start regular VM shutdown.
  If a VM does not respond within five minutes, the server remains powered on.
- Check schedule behavior; available sleep and wake types depend on hardware.

6. HOME NETWORK AND PRESENCE
- Discover devices in the local network and display their online/offline status.
- Maintain names, device types, and assignments.
- Display IP addresses, MAC addresses, manufacturers, and last contact time.
- Manage client agents and presence detection.
- Consider suitable devices as sleep blockers.
- Detect or configure network interface and subnet area.
- Disable monitoring on secondary servers.

7. DYNDNS AND SERVICE TARGETS
- Manage DynDNS providers and hostnames, including INWX and DD NSS.
- Check public IPv4/IPv6 addresses and update them via timer.
- Display status, errors, wait times, and next run time.
- Adopt existing supported script configurations.
- Display detected local Apache targets and redirects.
- Assign hostnames to applications like Nextcloud or Immich and store ports.
- Check DNS resolution and TLS certificate with a single click.
- Compact, expandable target overview with uniform naming conventions.
- Choose Reverse Proxy or browser redirect via own setup dialog;
  enter target address and port. The proxy keeps the domain in the browser.
- Optionally set up new Apache proxy connections with HTTP, existing certificate,
  or a new Let's Encrypt certificate after verification.
  Pure target assignment remains a note only. DNS, router shares, and
  required trust settings for the target application are configured separately.

8. VIRTUAL MACHINES (KVM/LIBVIRT)
- Display existing VMs and start, shut down, or restart them.
- Create, import, and clone supported VMs.
- Export the system disk of powered-off VMs as RAW (.img) or compressed QCOW2
  for Rescuezilla. Perform image comparison and download per VM and job.
  Individual disks without additional drives, NVRAM, or TPM state; hardware boot
  may require driver or bootloader repair. No bootable installation ISO available.
- Select ISO and disk files via freely selectable server folders and subfolders.
- Predefine Rescuezilla backup folder and optional startup ISO in settings;
  still selectable per job in the VM form.
- Choose a target drop location for each new VM; create a new VM folder there
  and check free space on the target drive. The general VM path remains unchanged.
- Prepare a Rescuezilla/Clonezilla backup of an individual disk for a new VM:
  Rescuezilla ISO, target disk, and read-only backup copy. Perform restoration
  subsequently in Rescuezilla; instructions provided within the VM.
  Original size and additional storage are checked. No automatic resizing,
  no multi-disk or 4K sector restoration. The medium can be unmounted afterward;
  the additional copy remains on the server.
- Manage CPU, memory, drives, networks, and auto-start settings.
- Install KVM dependencies and set up a network bridge.
- Backup supported powered-off VMs including disks, configuration,
  and existing UEFI/TPM data.
- Download ready-made VM backups directly. New archive names include
  VM name, date, time, and a unique job number.
- Upload backups and restore them as new, initially powered-off VMs.
- View progress, jobs, and error logs.
- Without configured KVM, do not report an incorrect sleep blocker; if the
  detected installation is impaired, protection remains active.
  RAM states, ISO files, snapshot history, and special host bindings are not
  part of this complete VM backup scope.

9. APPLICATIONS AND UPDATES
- Detect supported applications and manage them in custom cards.
- The home page card lists installation, uninstallation, updates, backup,
  and restore options.
- Display installation status, reachability, and available updates.
- Install, uninstall, or hide applications based on support availability.
- Manage examples such as Nextcloud, Open WebUI, Pi-hole, Plex, Jellyfin
  and KVM.
- Consider Nextcloud as a native installation or Docker installation.
- Detect existing Nextcloud installations at common paths, in web server
  configurations, and within Docker; verify detected mappings before takeover.
- Install Nextcloud locally or via VPN without a public domain.
- Later supplement domains and HTTPS for local installations set up by the
  manager; display existing addresses and certificates to retain local access.
- Display supported Apache redirects, add, edit, disable, re-enable,
or remove them. Disabling returns HTTP 410 so that previous addresses do not
  inadvertently serve other content.
- Use app-specific backups, restorations, checks, and logs.
- Check, prepare, and execute updates for supported apps.
- Schedule automatic update checks with prior APT package list refresh.
- Refresh APT package lists, display available updates, and start upgrades.
- Download Qwen models for Ollama and remove installed models. Functionality
  varies depending on the application and installation type.

10. BACKUP AND RESTORATION
- Store server and client backups in a central backup folder.
- Use manual as well as scheduled backups, including incremental profiles.
- Execute daily backups sequentially and monitor their status.
- Backup app data, configurations, and supported databases.
- View backup inventories, timestamps, logs, and supported restorations.
- Provide client helper tools for backup and restoration,
  also accessible from a live USB system.
- Optionally align user and group IDs between client and server.
- Copy existing backup folders including VM and internal restore points to an
  additional drive selected by UUID; add extra sources as needed.
- Perform the first external copy fully, then copy new/changed files and reuse
  unchanged files via hard links. Old states remain preserved.
- Mount if necessary for execution and subsequently unmount;
  check space requirements, filesystem UUIDs, contents, and permissions.
  No formatting required.
- External job runs independently of the web service and blocks scheduled sleep.
  Linux filesystem required. No new application backup or system image; incomplete
  source backups remain incomplete. Do not modify sources during operation;
  do not edit external restore points due to shared files. Which data is included
  is determined by the selected backup profile.

11. DOWNLOADS AND UPLOADS
- Offer files from a designated main folder and its subfolders in the browser.
- Download files and upload new files to the main folder.
- Define the provided folder centrally in settings.

12. PHOTO LABORATORY
- Check image repositories and list damaged or uncheckable files.
- Find content-duplicate duplicates and download reports.
- Verify JPEG/DNG associations and clean up unnecessary DNGs based on previews where appropriate.
- Utilize supported repairs and recovery options for images.
- Convert compatible RAW formats to DNG using the matching converter.
- Create photo shows from an image repository.
- Track progress and verification history; pause and resume supported jobs.

13. SCANNER API FOR HOME ASSISTANT
- Install and verify the Scanner API and its dependencies; create the default scanner account as needed without interactive login.
- Configure scanner address, protocol, device ID, API port, and output folder.
- Select service user and access group; display folder permissions and set them for the target folder as well as new scans. Existing scans remain unchanged.
- Provide scan processes for PDF, JPG, and TIFF via the Scanner API.
- Check reachability and device detection separately.
- Step-by-step guide for configuration.yaml with existing sections and offloaded YAML files; verify configuration, reload, and test scanning.
- Download appropriate YAML configuration for Home Assistant.

14. TV AND RECORDINGS
- Connect Tvheadend and display its status.
- Search the television program by title, channel, station tag, date, and time.
- Display scrollable program overview with shows per channel.
- Pass individual recordings or series recordings to Tvheadend.
- Mark scheduled recordings in the EPG colorfully.
- Browse recordings, sort by age, and delete selected recordings.
- Consider live TV streams, recording scheduling, and wake-up times.
- Automatically hide the TV section if installation is missing.

15. WEB AND SECURITY
- Install Apache, certificates, and Fail2ban and check their status.
- Examine local and actually issued certificates separately.
- Create certificates for domains, verify renewals, and remove certificates.
- Consider usage of a certificate before deletion.
- Edit supported Apache configurations with verification and restore.

16. ALARMS
- Centralize warnings and optionally send them via ntfy.
- Monitor storage, SMART, backups, DynDNS, certificates, and selected services.
- Optionally report VM errors: failed/interrupted jobs, crashes, disrupted libvirt connections, and VMs not shut down after five minutes.
- Report errors of external full backups via the backup alarm source.
- Set check interval and time for daily repetitions.
- Use alarm preview and test messages.
- Indicate hard drives in notifications with mount names and mount points.

17. SETTINGS, INSTALLATION AND MAINTENANCE
- Centrally adjust and save server and module paths.
- Select modules and view module diagnostics.
- Display package version and author note under Settings / Info.
- Execute repair scripts with description directly, e.g., for XRDP/XFCE.
- Install the manager via DEB package or update via a DEB upload.
- Display the last two manager updates; older logs remain preserved.
- Detect manual installations before a DEB upload and protect against overwriting.
- Clean up old Python caches during package update; the updated updater additionally checks the version of the started manager.
- Adjust web port during installation.
- In the installation script, select optional initial setup, SSH/desktop access, and adding a user to the sudo group.

IMPORTANT OPERATIONAL NOTES
- Network, router, and application functions require appropriate configuration.
- Complete ongoing backups before manager updates or restarts; a restart can interrupt background jobs.
- A successful backup does not replace occasional restore tests.
- This overview contains no personal addresses, credentials, or server paths.
