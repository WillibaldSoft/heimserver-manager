HTTPS SYSTEM BACKUP AND RESTORE – LINUX CLIENT 0.4.31
Updated: 2026-10-11

SHARED SYSTEM, SEPARATE USERS
A PC has one shared system snapshot and separate personal snapshots.
The stable device identity identifies the PC, rather than its changeable name.
Before backup, the client checks for existing completed snapshots.
An existing system snapshot is reused. After changes to the system, applications
or selected additional volumes, explicitly select “Refresh shared PC system
snapshot”. This does not happen automatically.

An authenticated Manager administrator or explicitly authorized user may create, refresh or download
shared system snapshots. A paired user without that permission sees only whether a shared snapshot
exists and its date. They back up and read their own personal data. If no system
snapshot exists, home data is still backed up, with an explicit missing-system
notice. Every user must back up their own home; other homes are not collected
without asking. Personal backups run without local root privileges.

COVERAGE
System: applications, package database, repositories and keys, system configuration,
accounts/UID/GID, services, ACLs/xattrs and selected additional volumes.
Normal user homes are excluded from the shared system snapshot.
Additional local disks and mounted shares require selection; choose mountpoints
outside user homes for additional shared volumes.
Network profiles containing credentials require separate explicit selection.
Personal: your own home below /home, including hidden files, user applications,
desktop settings, links, ACLs and your own inventories.
No nested mounts or automatically backed-up network homes.

INCREMENTAL AND DIRECT
Transfer uses verified HTTPS, without a share or local intermediate archive.
Personal files are reread; only new/changed 4-MiB blocks are transmitted.
Shared system snapshots have a separate block store per PC; personal blocks
remain isolated per account/profile. Shifted block boundaries may cause additional
transfers. Each snapshot is fully downloadable.
Unfinished snapshots never count as successful backups. The client can discard
unfinished personal uploads; shared uploads require Manager administrator sign-in.
Completed snapshots and their referenced blocks are retained.

RESTORE
On a newly prepared target, restore the system snapshot as Manager administrator
first, then the users’ desired personal snapshots.
On an already configured PC, restore only personal data.
System file restore: live system, matching distribution/version/architecture,
prepared target partitions; the target’s fstab/crypttab are retained.
Personal: home restore from a live system, individual files into a new directory,
or personal migration into the running target with confirmation and recovery copies.
Personal migration restores only home and user settings, not shared system components.
The target client profile and autostart are retained.
Your other paired PCs are accessible with your own Manager account; other users’
personal snapshots remain inaccessible. Shared snapshots require an administrator.
Download and verification copy require at least twice the archive size plus reserve;
migration also requires space for unpacked data. Verify checksums before changes.

LIMITATIONS AND EXISTING BACKUPS
Old combined archives are neither shared nor changed. They remain in their original
account/profile. New shared snapshots must be created once.
The USB/NFS wizard and offline sources remain a separate workflow.
No automatic partitioning/bootloader installation or sector image. For other
distributions, review compatible target packages and components.
Shut down running databases, VMs and containers cleanly first. No guaranteed
application-consistent snapshot. No archive encryption at rest.
Session expiry still applies during backup; sign in again before long runs.
Windows client unchanged.

Linux client 0.4.30 (2026-10-11): “Cancel backup” during HTTPS system/home/folder backups and local ZIP file backups. The current section may still need a response. Inventory/archive helpers receive a cancellation signal; only the specific unfinished upload ID is discarded. Completed snapshots and shared referenced blocks are retained. If completion has already been confirmed, the snapshot is retained; an unreachable server produces a pending-cleanup notice. Manager administrators can also cancel running/unfinished desktop uploads under Backup & Recovery → Desktop Client Backups. The separate interactive USB/NFS system wizard and restores do not receive a blanket forced stop. An already running older client gets the new button only after updating and restarting.

User permission for PC system snapshots (2026-10-11): Under Settings → Manager users, an administrator can enable “Allow PC system backup and system recovery”. Requires the User role and Own clients & backups. Grants access to all shared PC system snapshots, including sensitive system files. Other users’ personal backups and server backup jobs remain restricted. Disabled by default; changes revoke existing account sessions. Agent tokens do not receive these rights.
