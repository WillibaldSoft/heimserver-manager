HOME SERVER MANAGER – CHANGES PER VERSION
This file is continued with each new DEB version.
Review since 0.12-18 based on created packages and documented changes.

0.13-9 – October 22, 2026 – Beta
- Applications / System packages: opt-in security update automation every two hours. Official Debian/Ubuntu security repositories; Mint uses its Ubuntu base. New installations remain disabled initially.
- Persistent APT jobs and sleep blockers protect running updates. Backups and installations defer the run; the server is not woken. Package holds and blacklists remain effective.
- needrestart restarts affected services, then checks again. Outstanding security updates, services and server reboot requirements are shown. No automatic server reboot and no full CVE or critical-only scan.
- ntfy reports installed updates, failures and pending restarts using the existing alarm configuration. Unchanged alerts are suppressed; only counts are sent without detail consent.
- Completion checks are explicitly recorded in status and logs. Read-only diagnostics also recognize older completed runs from their stored verification results instead of incorrectly reporting False.
- Linux client 0.4.41 and Windows client 0.2.12 remain unchanged. German and English documentation updated.

0.13-8 – October 18, 2026 – Beta
- Linux client 0.4.41: clickable software download link at the bottom left, derived from the configured manager address. Without a valid address, the example link remains disabled.
- Version number shown only in the window title; duplicate version line removed. German and English labels.
- Includes the history layout and all documented fixes from interim releases 0.13-4 through 0.13-7. Windows client remains 0.2.12 (experimental).

0.13-7 – October 18, 2026 – Beta
- Linux client 0.4.40: new server-side offline recovery copies are stored in hidden .hsm-history directories, grouped by UTC timestamp and unique ID, retaining full original filenames.
- History directories remain excluded from offline synchronization. SMB deletions and HTTPS replacements retain the original inode, ownership, file permissions and ACLs. SMB replacements still use a verified ACL copy; insufficient permissions are not bypassed.
- Legacy recovery copies are retained; installation does not automatically migrate or delete them. Original filenames cannot reliably be reconstructed without an existing mapping.
- Windows client remains unchanged at 0.2.12 (experimental). The new client-side SMB layout applies to Linux.

0.13-6 – October 18, 2026 – Beta
- Linux client 0.4.39: clear message when synchronization is already running; shared live progress for automatic and manual sync. Sign-in & setup appears at the bottom, with no reserved blank space while collapsed; compact main window.
- SMB deletions retain the original file by renaming it within the share. Ownership and permissions remain intact; Samba rights are not bypassed. Updates to existing files still use the previous ACL-checked recovery-copy method and may fail when permissions are insufficient.
- Update runs refresh status and results automatically; completion checks refresh app cards. Backup preparation continues polling after a connection failure without starting another job.
- Running app update checks prevent automatic shutdown; interrupted checks are detected after a manager restart. Open WebUI blockers observe locks without competing for them.
- Direct manager restart under Settings retains existing job checks. Visible, copyable client download addresses still require sign-in.
- Windows client 0.2.12 rebuilt from current source; remains experimental. The new GTK layout and Linux SMB fixes are Linux-specific. No native Windows runtime test for this release.

0.13-5 – October 11, 2026 – Beta
- Linux client 0.4.38: backup workflow organized by account, scope, actions and progress. Advanced options collapse; signing in no longer opens duplicate dialogs. Long status messages scroll separately to keep actions accessible.
- Wide scrollbars appear only when needed and remain visible while content overflows. Larger initial settings, offline-file, backup and restore windows fit the monitor work area.
- Cancelling block-based backups retains uploaded blocks for the next incremental run. All source files are still read; only unknown blocks are uploaded. Simple folder/ZIP backups and the USB assistant remain unchanged.
- Delete completed server snapshots after account sign-in and explicit confirmation. Shared blocks and system baselines referenced by personal snapshots are protected. Active downloads lock their storage against concurrent deletion.
- Administrator tool re-indexes existing block archives without changing archive size, SHA-256 or snapshot ID. Requires a maintenance window and temporary additional storage. Package installation never automatically migrates or deletes existing backups.
- Matching backup UI and implementation shipped together, including incomplete-upload confirmation, offline-copy exclusion and content-defined chunking.

0.13-4 – October 11, 2026 – Beta
- Linux client 0.4.37: content-defined block boundaries for incremental HTTPS system and personal backups. Insertions and deletions no longer permanently shift all subsequent boundaries. SHA-256 verification and byte-exact restoration remain in place; no local temporary archive.
- The first run after migration may create many new blocks; older snapshots remain readable and unchanged. Files are still read in full. Previous reading positions are not resumed. Blocks range from 1 to 4 MiB, with a smaller final block; maximum 262144 blocks per snapshot, so capacity depends on block sizes.
- Configured local offline copies of all normal users are excluded from new shared system snapshots by default, including size estimation. A visible option allows inclusion and requires a new system snapshot. Additional filesystems still require separate selection. User homes remain separate; existing system snapshots are unchanged.
- Tests cover insertion, deletion, different input fragment sizes, absent content anchors, server-side verification and restoration. Windows, simple folder backups and the USB assistant are unchanged.

0.13-3 – October 11, 2026 – Beta
- Linux client 0.4.36: readability preflight for HTTPS system and personal backups. List inaccessible paths, exclude them for this run only after explicit confirmation, and record exclusions in the inventory. New read errors during transfer still fail the backup. Local per-user exclusions remain supported; packages contain no private exclusions.
- Show incomplete incremental uploads and retire them after confirmation while preserving blocks and completed snapshots. Read files again and reuse identical blocks. Other devices, running verification, changed uploads and activity within ten minutes prevent retirement. Do not replace paused uploads.
- Background checksum verification with status polling and verification progress instead of one long HTTP request. Mark complete only after successful verification. A lost connection or service restart leaves completion unconfirmed; do not discard data prematurely.
- Personal inventory shows the home filesystem and excluded nested mounts. Clear read errors without an additional desktop crash report.
- Update manager and client together; manager changes require a checked restart. Run-scoped authentication requires the updated running manager. Package builds do not change running services or backups. Windows and simple folder/USB backup modes do not receive these Linux HTTPS extensions.

0.13-2 – October 11, 2026 – Beta
- Linux client 0.4.35: HTTPS backups continue after normal login expiry using a separate credential scoped to the account, device and backup run. It is closed at the end and expires after 24 hours without API activity. Account locks and revoked permissions still apply. No passwords are stored.
- Older managers retain the sign-in-again fallback for paused backups; the account and server must remain the same. Previously terminated transfers are not retroactively resumed.
- Progress bar from 0 to 100 percent for Linux HTTPS system backups: estimate size from file metadata, weight new system and personal components, and count both transferred and reused blocks. Server verification is separate; 100 percent appears only after successful completion.
- Size estimation uses the same mount and home exclusions as the backup. No temporary local archive. Sparse files, archive metadata and changes during a run limit estimate accuracy. Simple folder backups, the USB assistant and the Windows client are unchanged.
- Offline files no longer automatically restore known local deletions when write-back is disabled; an explicit hint explains the required two-way and deletion options.
- New tests cover expired sessions, run-scoped permissions, cancellation and size-based progress. New Linux clients require the matching manager update for unattended backups.

Client 0.4.35 – October 11, 2026
- Offline files: a known local deletion remains pending instead of being downloaded again when two-way sync or deletion propagation is disabled. Both options are required to delete the server copy. Concurrent server changes remain conflicts; files without a previous sync baseline are treated as new server files. Existing folder settings are not changed automatically.

A metadata scan uses the same mount exclusions; sparse files and archive metadata make the estimate approximate. No temporary local archive is created. The separate USB assistant and simple folder-backup flow are unchanged.

0.12-67 – October 10, 2026
- Offline files: select a user/client first, then edit its folder assignments. Only mounts and configured SMB/NFS share roots are selectable; no subdirectories are enumerated. Other clients and existing permissions are preserved.
- Offline files: deeper subfolders selectable in Linux/Windows clients (0.4.8 / 0.2.10). Existing SMB/NFS/Linux rights replace extra write grants; ambiguous rules are refused. File operations run as the paired Linux user, not the emergency ADMIN account.

- Nextcloud/DAVx5 waking: Active, Inactive or daily schedule with up to eight non-overlapping periods, including overnight, and a default outside periods. Uses gateway host local time. Recovery API, Home Assistant and client wake commands remain independent; running servers remain accessible.

- Added offline files (beta) for Linux and Windows clients: separate folder grants, HTTPS, conflict protection and expiring sleep blockers. Changed files only, no block-level synchronization.
- Diagnostic logs record reasons for resetting the shutdown grace period and wake requests. Wake logs exclude full URLs, credentials and raw client IP addresses and have a limited logging rate. Earlier triggers cannot be reconstructed retroactively.

Linux client 0.4.9 (2026-10-10): Existing SMB/NFS mounts are detected and can be associated with an offline share. Transfers continue over HTTPS; no mounts are created or modified. Offline destinations inside, above or equal to known network mounts are rejected; saved associations also protect unmounted paths. Windows client unchanged.

Linux client 0.4.10 (2026-10-10): After explicit confirmation and administrator authorization, a simple SMB/NFS fstab mount can be replaced by a link to the local offline folder. A conflict-free HTTPS synchronization runs first. The existing path remains usable; fstab and the mount directory are backed up. Returning to the network mount requires confirmation and retains local files. Busy mounts are never forcibly detached. Automounts, custom mount services and writable mount parent directories are not automatically converted. Samba offline data currently synchronizes read-only; local edits are not uploaded to the server.

Linux client 0.4.11 (2026-10-10): Confirmed offline switching now supports native systemd automount units and fstab-generated SMB/NFS automounts. A dedicated persistent start condition prevents remounting during offline use. Original units, fstab entries and enablement remain unchanged. Previous active/inactive states are saved and restored when switching back. Busy mounts are never forcibly detached; changed unit configurations and overridden start guards are rejected. A successful conflict-free HTTPS synchronization, confirmation and administrator authorization remain required.

Linux client 0.4.12 (2026-10-10): “Use mount path for offline files” automatically suggests a separate local storage folder. An existing configured local folder is retained; invalid network destinations are rejected. Confirmation shows the usual access path and local storage location before saving settings, synchronizing files or changing mounts. Conflict-free synchronization and administrator authorization remain required.

Linux client 0.4.13 (2026-10-10): Create or adopt local offline folders directly in the client. Write access is checked before saving or synchronizing; where needed, explicit administrator authorization creates the folder or changes its owner. No recursive permission changes and no client running as root. Network mounts and system folders are excluded. Privileged creation requires an existing protected parent directory.

Linux client 0.4.14 (2026-10-10): Two-way synchronization for supported SMB shares with an additional SMB login. Passwords are stored only in the local keyring; HTTPS read access and existing manager assignments are still required. Samba enforces write and inheritance permissions. Existing files retain their owner and ACL during updates; previous content is retained on the server with verified permissions. Interrupted writes may leave incomplete server content: keep the local file and retained revision, review the conflict and resolve it explicitly. Diverging revisions are never silently overwritten.
Per-folder options remain editable: synchronize at login / client startup and before shutdown. Shutdown never wakes the server; if unreachable, proceed immediately after a brief connection check. Otherwise wait at most 60 seconds, additionally capped by systemd-logind (often 5 seconds). The client must be running; forced power-off cannot be intercepted. Errors and timeouts remain visible as pending. The next startup retries if startup synchronization is enabled. New package dependencies: python3-smbc and libsecret-tools. Windows client unchanged.

Linux client 0.4.15 / Windows client 0.2.11 (2026-10-10): Removed the 256 MiB offline file limit, including support for larger ISO files. Transfers use bounded chunks; storage quotas, free space, permissions and timeouts still apply. Temporary server storage requires the file size plus a 512 MiB reserve. Links and special files remain excluded.

Linux client 0.4.16 (2026-10-10): Selecting a network mount suggests an offline destination matching its folder structure, inserting Offline between the parent directory and mount name. The suggestion remains editable. Existing assignments are retained when opening the dialog; existing files are not moved automatically.

Linux client 0.4.17 (2026-10-10): New “Include all server subfolders” button selects the entire assigned server folder and clears exclusions after confirmation. Files in deeper subfolders are synchronized recursively. Review the destination and save; no immediate sync is started. Permission checks remain in force; empty directories, links and nested mounts are not included.

Nextcloud wake fix (2026-10-10): Recognized Nextcloud desktop background polls (DAV PROPFIND and selected status endpoints) no longer wake the server or extend sleep blockers. Sleeping servers return HTTP 503 with a retry hint for these polls. File transfers and DAVx5 remain protected. Other clients and unknown requests retain existing behavior; classification is not authentication.
